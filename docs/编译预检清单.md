> 读完应该是"知道该做什么"，而不是"不知道该不该信这份代码"。

## 二、静态层面已经拦过的（不用再靠人肉检查）

跑 `node tools/check_swift.mjs`，它拦这 6 类：

1. 括号配平
2. 顶层类型重名
3. 框架 import 漏项（反查表）
4. struct 有 private 存储属性却又需要外部传参构造 → 逐成员初始化器降级成 private
5. 构造调用实参顺序 ≠ 存储属性声明顺序（**Swift 的逐成员初始化器参数顺序 = 声明顺序**）
6. 关键令牌落地 + 旧版配色回流

**这个脚本自己也误报过**：第一版报出 15 个问题，其中 14 个是它自己的错
（把计算属性当存储属性、把三元里的 `.alert` 当成实参标签）。都修了，修法写在脚本头部注释里。
—— 看到红色先怀疑脚本。

## 三、只有编译器能裁决的三类（各给两种修法）

### 1. `#Predicate` 宏的捕获限制
- **本工程现状：不涉及。完全没有用 SwiftData / `#Predicate`。**
- 规避方式就是不用它：数据层是 `Codable` + 单个 JSON 文件。
- 若以后要上 SwiftData：① 谓词里只写内联字面量，**不要捕获变量**、不要写三元或分支；
  ② 复杂过滤挪到内存里做（用 `Array.filter`），个人级数据量完全够。

### 2. Swift 6 严格并发下 delegate 的 `nonisolated` 标注
- **本工程现状：`SWIFT_VERSION = 5.0` + `SWIFT_STRICT_CONCURRENCY = minimal`**，不会被升级成错误。
- 想主动复现这些问题：把 `project.yml` 里 `SWIFT_VERSION` 改成 `"6.0"` 再编译。
- 真出问题时的两种修法：① 给 delegate 类型标 `@MainActor` 并让回调走 `MainActor.assumeIsolated`；
  ② 用 `nonisolated` 包一层，把跨隔离的访问收进一个显式的 `Task { @MainActor in ... }`。

### 3. 自定义 `Layout` 协议
- **本工程现状：不使用自定义 Layout。** 布局全走系统栈（`VStack/HStack/ZStack`）+ `frame`。
- 若以后要自定义布局：① 先能用 `GeometryReader` + `frame` 凑出来就别上 `Layout`；
  ② 上 `Layout` 时把 `sizeThatFits` 与 `placeSubviews` 的提案尺寸都当**建议值**处理，不可假定唯一。

## 四、修复协议（拿到编译结果后照这个走）

1. 在 Actions 里看那一步「摘出错误与警告清单」——**不要**去翻 3000 行原始日志。
2. 把 `error:` / `warning:` / `note:` 三类行**原样贴回来**（`note:` 经常是解释 error 的下一句）。
3. 按行改，**一次只改一类**：先全灭 error，再谈 warning。
4. 改完**重跑静态校验**（`node tools/check_swift.mjs`）防回归 —— 它守的是"改一处带崩另一处"。
5. 重新推，看清单是否变短。

**关于 warning 闸门**：流水线里有一条「有 warning 就失败」。这不是洁癖 ——
本项目的前身工程里，一条 `value 'c' was defined but never used` **从第 12 轮瞒到第 25 轮（连续 14 轮）**，
因为每轮只看绿勾、不看流水线自己数出来的条数。
代价要事先知道：runner 的 Xcode 升级带来新的 deprecation 警告时，CI 也会红。那是提醒不是回归。

## 五、编译通过之后，手动过这几条

1. **跑起来看首页**：示例数据（Mochi / Leo / 雪球 / 年糕 / 灰灰）会直接灌进 store，
   第一眼应该和画布 01 屏基本一致。不一致的地方（间距、阴影浓度）优先怀疑**阴影换算**那一项。
2. **切到浅色/深色系统外观**：应该始终是浅色（`UIUserInterfaceStyle = Light` + `.preferredColorScheme(.light)`）。
   如果跟着系统变深了，说明有一处漏了。
3. **看底部导航的内边距**：内容不能被悬浮胶囊盖住。它靠 `safeAreaInset(edge: .bottom)` 撑，
   若某一屏内容被盖住，说明那一屏的 ScrollView 被包在了 inset 之外。
4. **改一个令牌看是否全站生效**：把 `DS.primary` 改成别的颜色 → 应该所有按钮/进度/数字一起变。
   **如果有地方没变，那一处就是硬编码的裸色值**，静态校验只查了"旧版主色回流"，查不到新写的裸值。
5. **导出体积**：编译产物不该出现 `*.debug.dylib`。打包侧载时必须 **Release**
   （`ENABLE_DEBUG_DYLIB=NO` 已在 project.yml 里兜底）。

## 六、真机验收还差一条通道（现在别急着验）

**云端 CI 产出的是「编译结论」，不是「能装的包」。**
`CODE_SIGNING_ALLOWED=NO` → 产物**不签名**，装不进真机；而且现在连 `.app` 都不上传。

所以「等真机验」之前，先决定走哪条路：

| 路 | 需要什么 | 能验到哪 | 代价 |
|---|---|---|---|
| **借一台 Mac** | 任意 Mac + Xcode + 有线连手机 | 全部 | 最省事。免费 Apple ID 即可（**7 天过期**），下次改代码还得再借 |
| **付费开发者账号** | ¥688/年。证书 + 描述文件**在 Windows 上也能生成** | 全部，且以后不再需要 Mac | 唯一能闭环的路 |
| **Sideloadly + 免费 Apple ID** | Windows + Sideloadly（要装**网页版** iTunes + iCloud） | 基本能验 | 不花钱，7 天过期 |

**好消息：本工程不用 App Group**，所以免费 Apple ID 侧载那条路上最大的拦路虎
（`application-groups` 权限）**不存在**。三条路都可行。

真要出可侧载的包时，流水线还要加两步（**这两步现在没加，因为阶段一不需要**）：
① 打包改用 **Release**；② **上传前加一步拆包自检**（读三个 bundle 的 `CFBundleVersion` + 找 `*.debug.dylib`）。
理由：坏包不该变成用户能点的 Artifact —— 而他是照着指引点 Artifacts 的人，不会拆包看版本键。
